# مستندات جامع معماری، کارکرد و کاتالوگ وب‌سرویس‌های پلتفرم DiData Gold

---

## ۱. معرفی پلتفرم (Platform Overview)

**DiData Gold** یک زیرساخت سازمانی و پرسرعت برای تجمیع، پردازش، تحلیل و توزیع داده‌های لحظه‌ای بازارهای مالی است. این سامانه به‌گونه‌ای مهندسی شده که کسب‌وکارها، صرافی‌ها، فروشگاه‌های اینترنتی، نرم‌افزارهای حسابداری و مالی، و ربات‌های معامله‌گر بتوانند بدون دغدغه قطعی یا کندی، از نرخ‌های رسمی و دقیق بازار بهره‌مند شوند.

### اصول کلیدی طراحی سیستم:
* **سرعت پاسخ‌دهی فوق‌سریع (Sub-50ms Latency):** به لطف استفاده از معماری کش چندلایه‌ای حافظه، درخواست‌های کلاینت‌ها در کمتر از ۵۰ میلی‌ثانیه پاسخ داده می‌شوند.
* **پایداری ۹۹.۹٪ (High Availability):** استفاده از چرخه‌های همگام‌سازی پس‌زمینه و نگهداری آخرین داده‌های معتبر در حافظه پایدار، تضمین می‌کند سرویس حتی در زمان نوسانات اینترنت هرگز قطعی نداشته باشد.
* **تفکیک کامل ریال و تومان:** برای نخستین بار در ارائه‌دهندگان دیتای مالی، تمامی نرخ‌ها به صورت همزمان با مقادیر دقیق ریال و تومان بازگردانده می‌شوند تا خطاهای محاسباتی در سیستم‌های مالی و حسابداری به صفر برسد.
* **دسترسی سطح‌بندی‌شده (Tier-Based Plans):** پشتیبانی از پلن‌های اشتراکی رایگان، برنزی، نقره‌ای، طلایی و نامحدود، با کنترل ترافیک (Rate Limiting) هوشمند.

## ۲. سامانه چگونه کار می‌کند؟ (How It Works)

سیستم به صورت یک معماری ۴ لایه با جریان یک‌طرفه داده (One-Way Data Pipeline) کار می‌کند:

```
┌────────────────────────────────────────────────────────┐
│  ۱. لایه دریافت و همگام‌سازی پس‌زمینه (Engine Worker)   │
│  جمع‌آوری داده‌ها توسط کران‌جاب‌ها و دیمون‌های مستقل      │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  ۲. لایه اعتبارسنجی و تبدیل داده (Validation & Normalization) │
│  حذف نویز، اعتبارسنجی ارقام، محاسبه تغییرات و جهت بازار  │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  ۳. لایه کش دوگانه و پایگاه داده (Double Caching & DB) │
│  ذخیره آنی در فایل‌های کش اتمیک + ثبت در دیتابیس تاریخچه │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  ۴. لایه توزیع API و احراز هویت (API Delivery Layer)   │
│  اعتبارسنجی کلید API، کنترل سهمیه، و پاسخ‌دهی زیر 50ms │
└────────────────────────────────────────────────────────┘
```

### شرح لایه‌ها:

1. **موتور پس‌زمینه و دیمون مستقل (Background Daemon):**
   * سامانه‌ای مستقل به صورت دوره‌ای (هر ۳۰ تا ۶۰ ثانیه) فرآیند بررسی و گردآوری نرخ‌ها را اجرا می‌کند.
   * این فرآیند کاملاً مستقل از درخواست‌های کاربران است؛ بنابراین بار ترافیک کلاینت‌ها هرگز روی فرآیند بروزرسانی اثر منفی نمی‌گذارد.
   * مدیر سیستم در هر لحظه از پنل مدیریت امکان خاموش/روشن کردن کلید اصلی دریافت نرخ‌ها یا تک‌تک بخش‌ها را در اختیار دارد.

2. **لایه کش فوق سریع (In-Memory Atomic Cache):**
   * تمامی داده‌های پردازش‌شده به صورت ساخت‌یافته و استاندارد در ساختارهای ذخیره‌سازی فوق‌سریع ثبت می‌شوند.
   * هنگام ورود درخواست از کلاینت‌های API، نیازی به کوئری‌های سنگین دیتابیس نیست و پاسخ مستقیم از کش حافظه تحویل می‌شود.

3. **پایگاه داده تاریخچه سری‌زمانی (Time-Series Market History):**
   * تغییرات قیمت‌ها به صورت مداوم در جدول تاریخچه بازار ثبت می‌شود تا جهت رسم چارت‌های تکنیکال (شمعی/کندل‌استیک)، میانگین‌های روزانه، محاسبه حباب و کوئری‌های بازه‌ای مورد استفاده قرار گیرد.

4. **احراز هویت و امنیت (Security & Rate Limiting):**
   * احراز هویت از طریق کلیدهای اختصاصی ۳۲ بایتی ایمن صورت می‌گیرد.
   * هر کلید API دارای تاریخ انقضا، سقف مصرف روزانه، دسته‌بندی مجاز (طلا، ارز، رمزارز یا همه) و لاگ دقیق درخواست‌ها می‌باشد.

## ۳. کاتالوگ جامع وب‌سرویس‌ها (Available APIs)

تمامی درخواست‌ها به API با متد `GET` ارسال می‌شوند و نیاز به ارسال کلید API دارند:
* **از طریق هدر امنیتی:** `X-API-KEY: YOUR_API_KEY`
* **از طریق پارامتر URL:** `?key=YOUR_API_KEY`

فرمت تمامی پاسخ‌ها **JSON استاندارد با انکودینگ UTF-8** است.

### ۳.۱. وب‌سرویس طلا و سکه (Gold & Coins API)
* **آدرس اندپوینت:** `/api/v2/gold.php`
* **پوشش داده‌ها:**
  * **طلا:** طلای ۱۸ عیار، طلای ۲۴ عیار، مظنه تهران (طلای آبشده ۱۷ عیار)، انس جهانی طلا (XAU/USD).
  * **سکه:** سکه امامی (طرح جدید)، سکه بهار آزادی (طرح قدیم)، نیم سکه، ربع سکه، سکه گرمی.
* **فیلدهای خروجی هر آیتم:**
  * `symbol`: نماد یکتای استاندارد (مانند `IR_GOLD_18K`، `IR_GOLD_MELTED`، `IR_COIN_EMAMI`)
  * `name`: نام فارسی آیتم
  * `price`: قیمت روز به ریال
  * `change_pct`: درصد تغییرات روزانه (مثال: `+0.45%`)
  * `direction`: وضعیت نوسان (`high` برای صعودی، `low` برای نزولی)
  * `time`: زمان دقیق آخرین معامله
  * `high` / `low`: بالاترین و پایین‌ترین نرخ ثبت‌شده امروز

### ۳.۷. وب‌سرویس استعلام تاریخچه بر اساس تقویم شمسی (Shamsi Historical API)
این قابلیت منحصربه‌فرد برای هماهنگی با نرم‌افزارهای حسابداری و گزارش‌گیری سازمانی در ایران طراحی شده است:

1. **استعلام نرخ یک روز مشخص شمسی:**
   * **مسیر:** `/api/v2/shamsi_price.php?symbol=IR_GOLD_18K&date=1405-08-16`
   * **ورودی‌ها:** نماد مورد نظر (`symbol`) و تاریخ شمسی به فرمت `YYYY-MM-DD`.
   * **خروجی:** میانگین قیمت، کمترین، بیشترین، اولین و آخرین نرخ ثبت‌شده در آن روز شمسی.

2. **استعلام بازه تاریخی شمسی (Range Query):**
   * **مسیر:** `/api/v2/shamsi_range.php?symbol=price_dollar_rl&from=1405-08-01&to=1405-08-16`
   * **خروجی:** آرایه نقاط زمانی به تفکیک روز همراه با نرخ بازگشایی، بسته شدن، بیشترین و کمترین قیمت جهت رسم نمودار و مغایرت‌گیری.

## ۴. کدهای وضعیت و ساختار خطاها (Error Codes)

سامانه از کدهای استاندارد HTTP استفاده می‌کند:

| کد وضعیت | عنوان خطا | شرح |
| :--- | :--- | :--- |
| **`200 OK`** | موفق | درخواست با موفقیت پردازش شد و داده‌ها بازگردانده شدند. |
| **`400 Bad Request`** | پارامتر نامعتبر | پارامترهای ارسالی (مانند نماد یا تاریخ شمسی) ناقص یا نامعتبر هستند. |
| **`401 Unauthorized`** | عدم احراز هویت | کلید API ارائه نشده، نامعتبر است یا منقضی شده است. |
| **`403 Forbidden`** | دسترسی غیرمجاز | پلن اشتراکی کلید API شما اجازه دسترسی به این دسته یا اندپوینت را ندارد. |
| **`429 Too Many Requests`** | پایان سهمیه روزانه | سقف مجاز درخواست روزانه پلن شما به پایان رسیده است. |
| **`503 Service Unavailable`** | خطای موقت سرویس | سرویس موقتاً در حال به‌روزرسانی زیرساخت است. |

## ۵. نمونه کدهای اتصال سریع (Code Examples)

### اتصال با Python:
```python
import requests

url = "https://vb0.ir/api/v2/currency.php"
headers = {
    "X-API-KEY": "YOUR_API_KEY_HERE"
}

response = requests.get(url, headers=headers)
if response.status_code == 200:
    data = response.json()
    for item in data.get("items", []):
        print(f"{item['name']}: {item['price_toman']:,} تومان (ریال: {item['price_rial']:,})")
else:
    print(f"Error {response.status_code}: {response.text}")
```

### اتصال با PHP (cURL):
```php
<?php
$apiKey = 'YOUR_API_KEY_HERE';
$url = 'https://vb0.ir/api/v2/gold.php';

$ch = curl_init($url);
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER     => [
        'X-API-KEY: ' . $apiKey,
        'Accept: application/json'
    ],
    CURLOPT_TIMEOUT        => 5
]);

$response = curl_exec($ch);
curl_close($ch);

$result = json_decode($response, true);
print_r($result);
```

### اتصال با JavaScript (Fetch / Node.js):
```javascript
const API_KEY = 'YOUR_API_KEY_HERE';

async function getLivePrices() {
  const response = await fetch('https://vb0.ir/api/v2/currency.php', {
    headers: {
      'X-API-KEY': API_KEY
    }
  });
  const json = await response.json();
  console.log(json.items);
}

getLivePrices();
```

## ۶. نگهداری و گسترش‌پذیری (Maintenance)
* تمامی تنظیمات پلتفرم از پنل مدیریت قابل ویرایش است.
* فرآیند ثبت و مانیتورینگ وب‌سرویس‌ها در صفحه `admin/connections.php` در دسترس مدیران سیستم قرار دارد.
* به لطف طراحی ماژولار، افزودن نمادها، دسته‌بندی‌های جدید بازارهای مالی و گسترش متدهای محاسباتی به سادگی و بدون اختلال در عملکرد سرویس‌های قبلی امکان‌پذیر است.
